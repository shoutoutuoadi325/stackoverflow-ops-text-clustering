## Conclusion

The approx path is correct and has been verified on a controlled YARN smoke test, but the full-data `0.75/ht4/approx` profile is not a good final/demo profile on the current cluster resource envelope. It shows executor heartbeat pressure and severe long-tail tasks during the full approximate similarity join.

For the project defense, the recommended positioning is:

| Profile | Full-data result | Use in defense |
|---|---:|---|
| `yarn_sim065_ht2_bucket200` | 16 pairs, 16 clusters, 32 questions, 1665 s | Main demo/high-recall result |
| `yarn_sim085_ht4_bucket300` | 3 pairs, 3 clusters, 6 questions, 2603 s | High-precision comparison |
| `yarn_sim075_ht4_approx300` | Pressure test stopped at 7/37 stage-9 tasks after ~29 min | Engineering trade-off evidence |

This means the optimization improved correctness and defensibility by adding the official Spark ML approx path and proving it works on YARN smoke data, but the completed full-data evidence should continue to rely on the bucket strategy because it is faster and already produces reproducible evaluation outputs.
