# 最终实验复现说明

## 1. 前置条件

确认 `HDFS_FEATURES` 和清洗数据存在，并使用当前分支代码。当前 `topic_clustering.py` 已恢复最终运行版本所需的 `--training-num-features` 与 `--skip-silhouette`。

## 2. 基础运行

```bash
bash scripts/14_submit_cluster_intra_topic.sh k50 50
bash scripts/14_submit_cluster_intra_topic.sh k100 100
```

## 3. 4x 大 K 运行

```bash
bash scripts/16_run_k150_k200_pipeline.sh
```

该脚本默认：

```text
TOPIC_TRAINING_NUM_FEATURES=65536
TOPIC_SKIP_SILHOUETTE=1
RESCUE_TITLE_SIM_FLOOR=0.55
RESCUE_TAG_SIM_FLOOR=0.50
```

## 4. 2x 压缩对照

```bash
bash scripts/19_run_large_k_compression_controls.sh
```

生成 `k150c2` 和 `k200c2`，主题训练维度为 131072。

## 5. 单独运行 ORA 救援

```bash
RESCUE_TITLE_SIM_FLOOR=0.55 RESCUE_TAG_SIM_FLOOR=0.50 \
  bash scripts/15_submit_domain_rescue.sh k50
```

参数名 `RESCUE_TITLE_SIM_FLOOR` 是历史名称，实际控制完整 token Jaccard。

## 6. 备用拆分路径

`scripts/18_run_split_k150_k200.sh` 使用 `split_topic_clusters.py` 将既有低 K 主题确定性拆分。该路径用于集群资源不足时的备用实验，输出标签带 `_split`，不得与六组 folding 结果混用。

## 7. 导出

每个 HDFS 标签目录导出：

- summary_csv
- topic_metrics_csv
- similar_pairs_samples_csv
- clusters_samples_csv
- hybrid/hybrid_summary_csv
- hybrid/baseline_vs_hybrid_csv
- hybrid/rescued_pairs_samples_csv
- hybrid/hybrid_clusters_samples_csv

仓库目录为 `output/intra_topic_results/<label>/`。

## 8. 复核

1. 六个标签 summary 与本地总表一致。
2. K=100/150/150c2/200/200c2 的 topic metrics 覆盖 152,758 个问题且无 error 状态。
3. k150/k200 的 Hybrid 边集合相同。
4. k150c2/k200c2 的 Hybrid 边集合相同。
5. 2x 与 4x 的边集合共同 37 条，而非完全一致。
