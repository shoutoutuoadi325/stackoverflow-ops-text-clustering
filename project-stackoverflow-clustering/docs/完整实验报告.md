# 运维文本聚类与相似问题发现实验报告

## 摘要

本实验根据课程项目要求，在三台 Linux 服务器上部署 Hadoop 3.3.6、Spark 3.5.1 与 Python 运行环境，构建 Spark on YARN 的分布式文本分析平台，并以 StackOverflow Oracle 数据库问答数据为实验对象，完成从原始 JSON 数据入湖、清洗、探索性分析、文本特征工程、主题聚类、相似问题发现到命令行 Demo 查询的完整流程。

实验数据包含 152758 个问题、203393 个回答、331642 条问题评论和 220296 条回答评论，总文本对象数为 908089。算法部分使用 Spark ML 的 RegexTokenizer、StopWordsRemover、HashingTF、IDF、Normalizer、BisectingKMeans 和 MinHashLSH，并通过连通分量算法将相似问题边合并为重复问题簇。最终实验在 HDFS 上生成 EDA、主题聚类、相似问题对和重复问题簇结果，并完成本地导出与 Demo 查询验证。

## 1. 实验目标

本实验围绕“运维文本聚类”主题，目标如下：

1. 按照部署教程完成 Hadoop、YARN、Spark 集群环境安装与配置。
2. 将 Oracle 数据库相关 StackOverflow 问答数据上传至 HDFS。
3. 使用 Spark 完成数据清洗、统计分析、文本特征提取和聚类计算。
4. 使用主题聚类理解 Oracle 问题主题分布。
5. 使用 MinHashLSH 和连通分量发现标题、标签、正文表达接近的相似问题。
6. 形成可复现的脚本、HDFS 输出、Demo 命令和完整实验报告。

## 6. 数据清洗与预处理

预处理阶段使用 Spark 读取 JSONL，并写出结构化 Parquet。主要处理内容包括：

1. 提取问题标题、正文、标签、得分、回答数、评论数等字段。
2. 对 HTML 正文进行清洗，去除 HTML 标签、HTML 实体、链接和多余符号。
3. 保留 `ora-xxxxx`、`sql`、`plsql`、`jdbc`、`c#`、`oracle11g` 等具有领域意义的 token。
4. 按回答得分降序选取每个问题的前 3 个高质量回答作为语义补充。
5. 构造聚类文本 `doc_text`。

文档构造策略如下：

```text
doc_text = title * 3 + question_body * 2 + tags + top_3_answers
```

该策略提高标题和问题正文的权重，同时利用高分回答补充语义信息。评论文本噪声较高，默认不加入主聚类特征。

## 7. 文本特征工程

Spark ML Pipeline 如下：

```text
RegexTokenizer
  -> StopWordsRemover
  -> HashingTF(binary=True)      用于 MinHashLSH
  -> HashingTF(binary=False)
  -> IDF
  -> Normalizer                 用于 BisectingKMeans
```

领域停用词除了英文通用停用词外，还包括 `oracle`、`database`、`question`、`answer`、`thanks`、`please`、`help`、`problem`、`issue`、`codeblock` 等常见但区分度较低的词。Oracle 错误码没有被移除，因为错误码通常直接代表故障类型，对相似问题发现非常重要。

## 8. 聚类与相似问题发现算法

### 8.1 主题聚类

主题聚类使用 BisectingKMeans，输入为归一化后的 TF-IDF 特征向量。该算法适合在 Spark 中处理较大规模文本向量，可用于观察 Oracle 问题的主题分布。

本实验参数如下：

| 参数 | 数值 |
|---|---:|
| `k` | 50 |
| `maxIter` | 20 |
| `minDivisibleClusterSize` | 1 |
| 特征向量 | TF-IDF + Normalizer |

输出字段包括 `question_id`、`title`、`tags`、`score`、`cluster_id` 和簇内 Top terms。

### 8.2 相似问题发现

相似问题发现使用 MinHashLSH 近似 Jaccard 相似度，输入为 binary HashingTF 特征。相似度定义如下：

```text
similarity = 1 - jaccard_distance
```

实验中最初使用 `approxSimilarityJoin`，但在全量数据上出现倾斜和超长任务。最终采用“LSH bucket 展开 + bucket 大小上限 + 显式 Jaccard 计算”的方式降低倾斜影响：

1. 使用 MinHashLSH 对每个问题生成 hash bucket。
2. 展开 bucket，过滤大小为 1 或超过上限的 bucket。
3. 在同一 bucket 内生成候选问题对。
4. 使用 token 集合计算真实 Jaccard 相似度。
5. 按阈值保留高置信相似边。
6. 对每个问题保留 Top-N 相似结果。

### 8.3 连通分量

相似问题对可以看作图中的边，问题可以看作图中的点。若多个问题通过相似边连接，则属于同一个重复问题簇。本实验未引入 GraphFrames 额外依赖，而是使用 Spark DataFrame 迭代传播最小标签实现连通分量。

为避免迭代时 DAG 过深导致 Spark 任务失败，实验加入了 checkpoint 与 localCheckpoint：

```text
similar_pairs -> edges
edges + labels -> min neighbor label
迭代更新 label
localCheckpoint 截断 lineage
groupBy(cluster_id) 得到重复问题簇
```

## 14. 遇到的问题与解决方案

### 14.1 服务器无法访问公网

问题：三台服务器只能访问内网，无法直接下载 Hadoop、Spark、JDK、Miniconda 和 Python 依赖。

解决：在本机先下载软件包和 wheel 文件，再使用 `scp` 上传到 master，并分发到 worker 节点后离线安装。

### 14.2 Spark on YARN 找不到依赖 jars

问题：YARN 容器需要访问 Spark jars。

解决：在所有节点安装相同路径的 Spark，并配置：

```text
spark.yarn.jars local:///opt/bigdata/spark/jars/*
```

避免每次提交作业时上传大量 jars，提高提交速度。

### 14.3 原始 JSON 不能高效并行读取

问题：原始文件是一个 JSON 大数组，Spark 直接读取时无法按行切分。

解决：先在本地转换为 JSONL，每行一个问题对象，再上传 HDFS，使 Spark 能够并行读取。

### 14.4 CSV 不支持数组字段

问题：导出样例结果时，Spark CSV writer 不支持直接写出 `array<string>` 类型的 `tags` 字段。

解决：导出 CSV 前使用 `concat_ws` 将数组转换为 `tags_text` 字符串字段。

### 14.5 LSH 候选边倾斜

问题：MinHashLSH 在低阈值或较多 hash table 下会产生过多候选 pair，部分 bucket 过大导致任务倾斜。

解决：使用 bucket 大小上限过滤超大 bucket，并将阈值调为高置信的 `similarity >= 0.85`，保证任务稳定完成。

### 14.6 连通分量迭代 DAG 过深

问题：DataFrame 迭代更新 label 时 lineage 变长，容易导致任务执行变慢或失败。

解决：设置 checkpoint 目录，并在每轮迭代中使用 localCheckpoint 截断 lineage。

### 14.7 worker1 运行不稳定

问题：实验中 worker1 出现 DataNode 写入慢和 JVM pause 较长现象，导致部分 Spark task 明显慢于 worker2。

解决：在完成部署验证后，将重计算任务稳定运行在 worker2，并将派生数据副本数设置为 1。该问题属于集群资源与硬件稳定性问题，后续可通过磁盘检测、IO 监控、YARN 日志和 GC 日志进一步定位。

## 17. 实验结论

本实验完成了三台服务器 Hadoop/Spark 集群部署，并在真实 StackOverflow Oracle 数据集上实现了完整的大数据文本聚类流程。实验表明：

1. Hadoop HDFS 适合存储原始 JSON、JSONL、Parquet 和聚类输出等多阶段数据。
2. Spark 能够完成 15 万级问题文本的清洗、统计、特征工程和聚类计算。
3. BisectingKMeans 能揭示 Oracle 问题的主题分布，但高维稀疏问答文本主题边界不明显，Silhouette 指标较低。
4. MinHashLSH 适合发现标题和 token 高度重合的近重复问题，但需要处理 bucket 倾斜和阈值选择问题。
5. LSH 相似边结合连通分量可以形成可解释的重复问题簇，适用于运维知识库去重和相似问题推荐。

后续可进一步引入 Sentence-BERT、SimCSE 或其他语义向量模型，对 MinHashLSH 召回的候选问题进行二阶段语义排序；也可以结合人工标注构建评测集，系统比较不同阈值、不同特征和不同算法的 precision、recall 与 F1。
