# 运维文本聚类项目实施文档

## 1. 项目目标

本项目面向 StackOverflow Oracle 数据库问答文本，构建一个基于 Hadoop 与 Spark 的文本聚类系统，将本质相同但表达不同的问题聚到一起，为问题去重、知识库整理和运维检索提供支持。

## 2. 数据集

数据来源为 Stack Exchange Data Dump，筛选标签为 `oracle-database` 的 StackOverflow 问题、回答和评论。

数据规模：

| 指标 | 数值 |
|---|---:|
| 问题数 | 152758 |
| 回答数 | 203393 |
| 问题评论数 | 331642 |
| 回答评论数 | 220296 |
| 总文本对象数 | 908089 |

每条数据包含 `question_id`、`title`、`body`、`tags`、`score`、`comments` 和 `answers`。其中正文为 HTML 文本，回答与评论为嵌套数组。

## 6. 数据预处理

原始 JSON 是一个大数组，不适合 Spark 并行读取，因此先转换成 JSON Lines。预处理阶段完成：

- 读取 JSONL。
- 提取标题、正文、标签、回答数量、评论数量、分数。
- 按回答 `score` 降序选取前 3 个回答。
- 去除 HTML 标签、HTML 实体和大部分符号。
- 保留 `ora-xxxxx`、`c#`、`jdbc`、`sql`、`plsql`、`oracle11g` 等技术 token。
- 写出结构化 Parquet。

文档构造策略：

```text
doc_text = title * 3 + question_body * 2 + tags + top_3_answers
```

标题和问题正文权重更高，回答只作为语义补充，评论默认不加入主聚类特征。

## 8. 特征工程

Spark ML Pipeline：

```text
RegexTokenizer
StopWordsRemover
HashingTF(binary=True)        -> MinHashLSH
HashingTF(binary=False)
IDF
Normalizer                    -> BisectingKMeans
```

领域停用词包括 `oracle`、`database`、`question`、`answer`、`thanks`、`please`、`help`、`problem`、`issue`、`codeblock` 等。没有移除 `ora-xxxxx`，因为错误码对去重非常关键。

## 9. 聚类算法

### 9.1 主题聚类

主题聚类用于展示问题主题分布，采用 TF-IDF 向量和 BisectingKMeans。默认 `k=50`，输出每个文档的 `cluster_id`、标题、标签、分数和簇内高频 token。

评价方式：

- Silhouette 指标。
- 簇大小分布。
- Top terms 人工可解释性。
- 抽样查看簇内标题一致性。

### 9.2 重复问题发现

去重采用 MinHashLSH 近似 Jaccard 相似度。当前主流程使用 Spark ML 原生 `approxSimilarityJoin`，让 `distance_threshold` 参与 LSH 候选生成；随后再对候选问题计算 token Jaccard distance 和 similarity 做二次校验。为复现实验中的抗倾斜结果，脚本仍保留 `--join-strategy bucket` 历史路径，可配合 bucket size 上限运行高召回展示配置。

流程：

```text
tokens -> binary HashingTF -> MinHashLSH
approxSimilarityJoin(distance_threshold) -> candidate pairs
token Jaccard distance / similarity 二次校验
jaccard_distance <= 0.25 且 similarity >= 0.75 -> similar_pairs
similar_pairs -> connected components -> duplicate clusters
```

阈值建议：

| 场景 | similarity | 说明 |
|---|---:|---|
| 宽松候选 | 0.55 | 召回更多，需要人工审核 |
| 推荐展示 | 0.65 | 召回更多样例，适合答辩展示和人工审核 |
| 平衡默认 | 0.75 | 当前 `app.conf` 默认配置 |
| 高置信去重 | 0.85 | precision 更保守，适合说明阈值取舍 |

## 10. Demo 功能

命令行 Demo 支持：

- 输入 `question_id`，展示所在重复问题簇。
- 输入关键词，搜索标题。
- 展示同簇相似问题。
- 展示 pair similarity。
- 展示 Top duplicate clusters。

示例：

```bash
bash scripts/07_query_demo.sh --top-clusters --limit 10
bash scripts/07_query_demo.sh --keyword "analytic function" --limit 10
bash scripts/07_query_demo.sh --keyword "group by" --limit 10
bash scripts/07_query_demo.sh --question-id 28753859 --limit 10
```

## 12. 风险与处理

| 风险 | 处理 |
|---|---|
| Spark 直接读取 JSON 数组慢或失败 | 先转 JSONL |
| HTML、代码块、链接噪声影响聚类 | 预处理去 HTML，保留技术 token |
| LSH 阈值过低导致簇过大 | 最终采用 0.85 高置信阈值，报告中说明 precision/recall 取舍 |
| GraphFrames 依赖复杂 | 使用 Spark DataFrame 迭代实现连通分量 |
| 资源不足 | 调低 executor memory、增加分区、限制 topN similar pairs |
