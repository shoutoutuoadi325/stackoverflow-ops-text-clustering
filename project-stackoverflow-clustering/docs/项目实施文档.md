# 项目实施文档

## 1. 目标

在 Hadoop/Spark 集群上完成 StackOverflow Oracle 问答的主题组织和重复问题发现，并保留可复现代码、HDFS 输出和可审计派生表。

## 2. 数据处理

原始数据为嵌套 JSON 数组。先流式转换为 JSONL，再上传 HDFS。清洗阶段去除 HTML 和噪声，构造：

```text
doc_text = title * 3 + body * 2 + tags + top_3_answers
```

同时抽取 `ora_codes`。评论只用于 EDA。

## 3. 特征

- `features`：HashingTF + IDF + L2 Normalizer，供 BisectingKMeans 使用。
- `term_features`：binary HashingTF，供 MinHashLSH 使用。
- 存储维度为 262144。
- 大 K 可通过 `--training-num-features` 只 folding 主题训练向量，不改变 `term_features`。

## 4. 最终算法

1. BisectingKMeans 生成 topic。
2. 每个 topic 由大到小依次运行 MinHashLSH `approxSimilarityJoin`。
3. LSH 内部只携带 doc_id 和 term_features，候选后再回填元数据。
4. 用完整 token 集合重新计算 Jaccard。
5. 共享 ORA 时加 0.10 boost，并支持同主题 rescue floor。
6. 每个 src 保留 Top 10。
7. 相似边写 Parquet 后重读，截断 lineage。
8. 15 轮标签传播生成 Baseline 簇。
9. 跨主题 ORA join 生成补边，去重后用 8 轮连通分量生成 Hybrid 簇。

## 5. ORA 跨主题规则

- ORA 文档频次：2 到 150。
- 必须跨 topic。
- 完整 token Jaccard >= 0.55；或者标签有交集且 token Jaccard >= 0.50。
- boost：0.10。
- 参数名 `title_sim_floor` 为历史命名，不代表只比较标题。

## 6. 大 K 配置

| 标签 | K | 主题训练维度 | 脚本 |
|---|---:|---:|---|
| k50 | 50 | 262144 | 14 |
| k100 | 100 | 262144 | 14 |
| k150/k200 | 150/200 | 65536 | 16 |
| k150c2/k200c2 | 150/200 | 131072 | 19 |

`split_topic_clusters.py` 是确定性拆分备用路径，不属于六组最终 folding 结果。

## 7. 验收数字

k50 Hybrid = 46 对、42 簇、87 个问题。
k150/k200 4x Hybrid 边集合完全相同。
k150c2/k200c2 2x Hybrid 边集合完全相同。
2x 与 4x 每组共同 37/42 条边。

## 8. 输出

Raw Parquet 和完整日志保留在 HDFS。Git 跟踪 summary、topic metrics、相似对样例、救援样例和簇样例。权威结果见 `docs/项目完成结果.md`。
