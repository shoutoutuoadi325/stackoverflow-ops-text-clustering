# 项目完成结果

本文档是项目当前完成状态的唯一摘要。代码以当前分支为准，运行结果以提交 `a9ddaff` 导出的六组 CSV 为准。

## 1. 已完成范围

- 三节点 Hadoop 3.3.6、YARN、Spark 3.5.1 环境已验证。
- 152,758 条 StackOverflow Oracle 问题完成 JSONL 转换、HDFS 入湖、清洗和 Parquet 化。
- 完成 EDA、TF-IDF 主题特征、binary HashingTF 相似度特征。
- 完成 K=50/100/150/200 主题划分、主题内 MinHashLSH、连通分量。
- 完成 ORA 错误码结构化抽取、主题内 boost/floor 和跨主题救援图。
- 完成 K=150/200 的 4x 与 2x 主题训练向量压缩对照。
- 完成派生汇总表、相似对样例、救援样例、簇样例与答辩材料。

## 2. 最终代码链路

```text
JSON -> JSONL -> HDFS
-> preprocess.py：清洗、标题/正文/回答加权、ORA 抽取
-> feature_engineering.py：TF-IDF + binary HashingTF
-> topic_clustering.py：BisectingKMeans，可选训练向量 folding
-> cluster_lsh_intra_topic.py：主题内 approxSimilarityJoin
-> 相似边写 Parquet 后重读，截断 lineage
-> 连通分量
-> domain_rescue_graph.py：共享 ORA 的跨主题补边
-> Hybrid 图、汇总 CSV 与样例 CSV
```

大 K 的确定性主题拆分 `split_topic_clusters.py` 作为备用稳定路径保留，但六组最终结果中的 `k150/k200/k150c2/k200c2` 来自向量 folding 方案，不应混为同一实验。

## 4. 进一步比较

| 比较 | 共同 Hybrid 边 | 集合 Jaccard | 结论 |
|---|---:|---:|---|
| k150 vs k200（4x） | 42/42 | 1.0000 | K=150 后完全收敛 |
| k150c2 vs k200c2（2x） | 42/42 | 1.0000 | K=150 后完全收敛 |
| k150 4x vs k150c2 2x | 37/42 | 0.7872 | 宏观指标稳定，微观边有扰动 |
| k200 4x vs k200c2 2x | 37/42 | 0.7872 | 宏观指标稳定，微观边有扰动 |

因此不能说 2x 与 4x “结果完全一致”。正确表述是：聚合指标一致，88.1% 的单边重合，集合 Jaccard 为 0.7872；压缩改变了少量主题归属和候选边。

## 5. 最终选择

- **主展示：k50 Hybrid**。覆盖最高：46 对、42 簇、87 个问题，最大簇为 4。
- **工程折中：k150 4x**。42 对、40 簇、82 个问题，平均相似度 0.7557；与 k200 的 Hybrid 边完全一致，继续增大 K 没有收益。
- **压缩对照：k150c2**。聚合指标与 k150 相同，但边集合存在 5 条差异，用于说明资源优化对微观候选的影响。

## 6. 结果边界

- K=50 的覆盖最高不等于真实 recall 最高，因为没有全量 ground truth。
- 现有 90 条标签来自历史 LLM-as-a-Judge 辅助评审，缺少逐条 review note，只作为辅助证据。
- 总 precision 为 0.6667；0.65 阈值分组为 0.8125。不同 run 的采样构成不同，不能据此断言阈值越高 precision 越高或越低。
- 不计算 recall/F1，不声称参数统计意义上全局最优。
- `topic_metrics.elapsed_seconds` 是逐主题计时求和，不是端到端 wall-clock。
